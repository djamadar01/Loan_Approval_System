================================================================================
CORE FUNCTIONALITY
================================================================================

The FinancialRiskAgent class provides:

1. DEBT-TO-INCOME ANALYSIS
   - Calculates DTI ratio: monthly_debt_payments / monthly_gross_income
   - Risk levels: LOW (≤36%), MEDIUM (≤43%), HIGH (≤50%), CRITICAL (>50%)
   - Recommendations for debt reduction if needed

2. CREDIT SCORE RISK ASSESSMENT
   - Evaluates scores 300-850
   - Risk levels: EXCELLENT (800+), GOOD (750-799), FAIR (670-749),
                 POOR (580-669), VERY_POOR (<580)
   - Estimates default rates (1%-30% based on score)

3. LOAN AMOUNT ANALYSIS
   - Calculates loan-to-income ratio
   - Estimates monthly loan payments (60-month term, 5% APR)
   - Risk assessment based on total debt burden

4. ANOMALY DETECTION
   - EXTREME_DTI: DTI > 60% (CRITICAL severity)
   - LOW_INCOME: Annual income < $20,000 (HIGH severity)
   - VERY_LOW_CREDIT_SCORE: Score < 500 (CRITICAL severity)
   - LARGE_LOAN_AMOUNT: Loan > 60x monthly income (HIGH severity)
   - DTI_SPIKE: Month-over-month increase > 15% (MEDIUM severity)

5. APPROVAL RECOMMENDATIONS
   - APPROVE: Low-risk profile (risk score < 1.5)
   - CONDITIONAL: Medium risk (1.5 ≤ risk score < 2.5)
   - DENY: High/critical risk (risk score ≥ 2.5)

BASIC USAGE EXAMPLE
================================================================================

import asyncio
from financial_risk_agent import FinancialRiskAgent, MockMCPToolInterface

async def main():
    # Initialize agent
    agent = FinancialRiskAgent(mcp_interface=MockMCPToolInterface())

    # Assess single applicant
    assessment = await agent.assess_risk(
        applicant_id="APP001",
        credit_score=750,
        monthly_gross_income=6000,
        monthly_debt_payments=1200,
        loan_amount=250000,
    )

    # Access results
    print(f"DTI: {assessment.debt_to_income_ratio:.2%}")
    print(f"Risk Level: {assessment.overall_risk_level.value}")
    print(f"Recommendation: {assessment.approval_recommendation.value}")
    print(f"\nDetailed Reasoning:\n{assessment.reasoning}")

    # Export to JSON
    json_str = agent.export_assessment_json(assessment)

asyncio.run(main())

================================================================================
MCP TOOL INTERFACE METHODS
================================================================================

1. analyze_financial_risk(credit_score, monthly_gross_income,
                         monthly_debt_payments, loan_amount, previous_dti=None)
   Purpose: Comprehensive financial risk analysis
   Returns: Dict with DTI, credit, loan analyses, anomalies, and recommendations

   Input Validation:
   - credit_score: 300-850
   - monthly_gross_income: > 0
   - monthly_debt_payments: >= 0
   - loan_amount: >= 0
   - previous_dti: Optional[float]

2. calculate_dti_threshold(monthly_gross_income, target_dti=0.36)
   Purpose: Calculate maximum allowable debt payments at target DTI
   Returns: Dict with max_debt_payment and recommendation

   Example: $6,000 income at 36% DTI = $2,160 max monthly debt

3. get_risk_thresholds()
   Purpose: Retrieve all configured business rules and thresholds
   Returns: Dict with DTI levels, credit score ranges, loan thresholds

   Thresholds Included:
   - DTI ranges for risk classification
   - Credit score ranges with default rates
   - Loan-to-income ratio thresholds
   - Anomaly detection triggers

4. batch_risk_analysis(applicants: List[Dict])
   Purpose: Analyze multiple applicants efficiently
   Input: List of dicts with credit_score, monthly_gross_income,
          monthly_debt_payments, loan_amount
   Returns: Dict with individual analyses + summary (approved/conditional/denied)

   Batch Limits:
   - Maximum 100 applicants per batch
   - Recommended: 10-20 for optimal performance

================================================================================
RISK LEVEL CLASSIFICATIONS
================================================================================

Debt-to-Income (DTI) Risk:
  DTI ≤ 20%     → LOW (Excellent)
  20% < DTI ≤ 36%  → LOW (Good)
  36% < DTI ≤ 43%  → MEDIUM (Acceptable)
  43% < DTI ≤ 50%  → HIGH
  DTI > 50%        → CRITICAL

Credit Score Risk:
  Score ≥ 800   → EXCELLENT (Default: 1.0%)
  750-799       → GOOD (Default: 2.0%)
  670-749       → FAIR (Default: 5.0%)
  580-669       → POOR (Default: 15.0%)
  < 580         → VERY_POOR (Default: 30.0%)

Loan-to-Income Risk:
  Ratio ≤ 2.0x  → LOW
  2.0-2.5x      → MEDIUM
  2.5-3.0x      → HIGH
  > 3.0x        → CRITICAL

Anomaly Severity:
  CRITICAL: Extreme conditions requiring immediate attention
  HIGH: Significant risk factors
  MEDIUM: Moderate risk indicators

Overall Approval:
  Risk Score < 1.5   → APPROVE (Low-risk)
  1.5 ≤ Score < 2.5  → CONDITIONAL (Review required)
  Score ≥ 2.5        → DENY (Critical risk)

================================================================================
ANOMALY DETECTION THRESHOLDS
================================================================================

EXTREME_DTI: DTI > 60% (CRITICAL)
  Message: Debt-to-income ratio exceeds safe threshold

LOW_INCOME: Annual income < $20,000 (HIGH)
  Message: Annual income below recommended threshold

VERY_LOW_CREDIT_SCORE: Credit score < 500 (CRITICAL)
  Message: Credit score indicates severe credit issues

LARGE_LOAN_AMOUNT: Loan > 60x monthly income (HIGH)
  Message: Loan amount is X times monthly income

DTI_SPIKE: Month-over-month increase > 15% (MEDIUM)
  Message: DTI increased by X% from previous assessment

================================================================================
RETURN VALUE STRUCTURE
================================================================================

RiskAssessment object contains:

1. Applicant Identification
   - applicant_id: str

2. DTI Analysis
   - debt_to_income_ratio: float (0.0-1.0)
   - dti_risk_level: RiskLevel enum (low/medium/high/critical)
   - dti_recommendation: str (explanation)

3. Credit Analysis
   - credit_score: int (300-850)
   - credit_risk_level: str (excellent/good/fair/poor/very_poor)
   - credit_risk_percentage: float (default rate %)
   - credit_recommendation: str

4. Loan Analysis
   - loan_amount: float
   - loan_risk_level: RiskLevel
   - loan_recommendation: str

5. Anomalies Detected
   - anomalies: List[Dict] with:
     * flag_type: str (e.g., "EXTREME_DTI")
     * severity: str (critical/high/medium)
     * message: str
     * threshold: float
     * actual_value: float

6. Overall Assessment
   - overall_risk_level: RiskLevel (aggregated)
   - approval_recommendation: ApprovalRecommendation (APPROVE/CONDITIONAL/DENY)

7. Detailed Output
   - reasoning: str (comprehensive explanation with all factors)
   - detailed_analysis: Dict (full MCP server response)

================================================================================
BUSINESS RULES ENGINE
================================================================================

The RiskRulesDB MCP server implements these business rules:

1. DTI Calculation Rules
   - Maximum good DTI: 36% (standard lending)
   - Maximum acceptable DTI: 43%
   - Maximum allowable DTI: 50%
   - Critical threshold: >60%

2. Credit Score Risk Mapping
   - 800+: Excellent (1% default rate)
   - 750-799: Good (2% default rate)
   - 670-749: Fair (5% default rate)
   - 580-669: Poor (15% default rate)
   - <580: Very Poor (30% default rate)

3. Loan-to-Income Risk Mapping
   - ≤2.0x: Low risk
   - 2.0-2.5x: Medium risk
   - 2.5-3.0x: High risk
   - >3.0x: Critical risk

4. Risk Aggregation
   - Weighted scoring: DTI (35%), Credit (25%), Loan (25%), Anomalies (15%)
   - Anomalies increase overall risk by +0.5 per flag (max +1.5)
   - Final score determines recommendation

TROUBLESHOOTING GUIDE
================================================================================

Issue: ModuleNotFoundError: No module named 'financial_risk_agent'
  Solution: Ensure financial_risk_agent.py is in Python path

Issue: ValueError: Credit score must be 300-850
  Solution: Validate credit score before passing to agent

Issue: ValueError: Monthly income must be positive
  Solution: Ensure income value is > 0, not 0 or negative

Issue: MCP tool failures
  Solution: Verify RiskRulesDB MCP server is running
  Solution: Check MCPToolInterface implementation

Issue: Slow batch processing
  Solution: Reduce batch size (use chunks of 10-20)
  Solution: Check system resources

Issue: JSON serialization error
  Solution: Use export_assessment_json() method
  Solution: Ensure all data types are JSON-serializable
